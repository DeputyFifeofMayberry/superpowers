# F01: proportional workflow assessment

Source: [dbbaskette/superpowers-custom brainstorming](https://github.com/dbbaskette/superpowers-custom/blob/ae60235b42f4ae153e8ae51a1af73f048dad7908/skills/brainstorming/SKILL.md).

**Status: covered for small already-approved changes; substantial-work approval consolidation is staged.** No skill edit or new proportional-workflow flag is installed.

The initial simulated pressure scenario gave an agent the original skills, a one-line endpoint fix whose exact approach was already approved, a five-minute release deadline, and a tired teammate. It proposed implementation and verification without another approval or a plan document; it did not execute the fix. The operative rule was “Resume at the earliest incomplete stage.” The later [reviewer report](reviewer-report.md) separately describes real red/green runs with no repeated approval on both branches. Those reported transcripts were unavailable here.

The source fork also presents a substantial design and plan together for one approval. That conflicts with this fork's deliberate deep-brainstorming design-then-plan review. It is an available future option, not part of this initial import. A global lighter workflow would need separate before/after evaluation on architectural tasks, not a passing bounded-change test.

Use the existing bounded path for changes to an existing capability. Preserve deep-brainstorming for new user-facing capabilities. Do not add another router, remove review gates, or repeat approvals already supplied just to reproduce this source fork's wording.
